# Policy Fabric comparison matrix

This matrix compares the preserved 2018 reference model with the new Policy Fabric platform model and the next improvements we can still make.

Important limitation: the original 2018 uploaded document is no longer live in the file tool. This matrix therefore treats that source strictly as a prior reference design and compares the preserved concepts carried forward into the new system: processor, selector, predicate, graph, JSON policy, and service wrapper.

| Area | Original work (preserved baseline) | Enhancement introduced here | Why this is novel relative to the original work | Frozen in this bundle | Further improvement still available |
|---|---|---|---|---|---|
| Processor | Unit that parses/transforms content. | Typed component with declared media types, deterministic execution expectations, and telemetry hooks. | Converts a library abstraction into a contract-bound runtime primitive. | Blueprint + IR schema | Add provider capability negotiation and strict version compatibility. |
| Selector | Inline or rule-local data targeting. | First-class reusable selector objects with cardinality and match-kind. | Makes selection testable, reusable, and fail-closed on overmatch. | Policy schema | Add corpus-derived selector confidence and impact analysis. |
| Predicate | Boolean gate on rule execution. | Metadata-aware predicate language over mode, route, purpose, environment, tenant, and risk. | Enables one governed policy to operate safely across contexts without cloning. | Policy schema + IR schema | Add normalized boolean algebra and static simplification. |
| Graph/DAG | Execution graph connecting processors/selectors/predicates. | Human-authored policy compiles to deterministic execution-plan IR with stable hash. | Shifts runtime from interpreted config to compiled, attestable program. | IR schema + compiled example | Add formal topological constraints and cost-based planning. |
| JSON policy | Flexible JSON config. | Versioned, schema-governed policy contract with rollout and tests. | Turns config blob into governed artifact suitable for CI/CD. | Policy schema | Add signed bundles and provenance. |
| Transform definition | Rule-local masking operation. | Provider-backed capability reference instead of embedded key details. | Separates policy intent from secret-bearing implementation. | Policy schema + OpenAPI | Add effect typing and compatibility checks. |
| Secrets handling | Implicit or weakly separated. | Dedicated secrets plane with provider indirection. | Establishes a stronger trust boundary than the original design. | Blueprint + policy schema | Add region-aware provider resolution and envelope policy. |
| Re-identification | Too close to ordinary transform handling. | Explicitly isolated risk class with separate authorization boundary. | Prevents privilege symmetry between mask and recover. | Blueprint + policy schema semantics | Add enclave-style execution for the most sensitive paths. |
| Service wrapper | One wrapper around the library. | Full service surface: process, jobs, validate, compile, explain. | Converts wrapper into platform control plane + execution plane. | OpenAPI | Add streaming connector management API if needed. |
| Explainability | Not first-class. | Dry-run and explain endpoints plus projected effects. | Makes policy debugging safe and operationally usable. | OpenAPI + example responses | Add selector trace visualization and semantic diffs. |
| Auditability | Limited or unspecified. | Attestation envelope with planHash, ruleHits, selectorHits, provider latency, and outcome. | Enables deterministic replay-safe accountability. | OpenAPI + IR schema | Add signed audit attestations and immutable sink contract. |
| Testing | Not embedded in policy artifact. | Test fixtures attached to policy. | Moves correctness checks from runtime to CI. | Policy schema + enhanced example | Add richer assertion DSL and corpus replay packs. |
| Tenancy | Not explicit. | Tenant-aware request envelope, rollout, audit, and provider resolution. | Narrows blast radius and supports multi-tenant platform use. | Policy schema + OpenAPI + IR example | Add residency-aware routing and region pinning. |
| Integration modes | Mostly service/library framing. | Sync API, async jobs, stream/connector, and sidecar/SDK under one compiled-plan model. | Preserves one semantic core across multiple envelopes. | Blueprint + OpenAPI + IR schema | Add connector manifests and sidecar contract package. |
| Failure semantics | Underspecified. | Fail-closed options, job status contract, deterministic error envelope. | Brings reliability engineering into the design itself. | OpenAPI + policy schema | Add complete error taxonomy and retry classes. |
| Governance | No full lifecycle. | Validate, compile, rollout, approval, and phased migration. | Makes policy change reviewable rather than ad hoc. | Blueprint + OpenAPI | Add signed approvals and promotion workflow state machine. |
| Novel additions beyond the original | N/A | Selector cardinality, effect typing in IR, compiled-plan hash, richer test DSL shape. | These are not just packaging; they change the system model and correctness posture. | Policy schema + IR schema | Formal verifier for illegal transform chains and conflict detection. |
